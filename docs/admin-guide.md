# 管理员手册

面向系统的管理员（`admin` 角色或内置管理员账号）。部署与故障处理见[运维手册](ops-guide.md)。

---

## 1. 账号与权限模型

| 角色 | 范围 | 能力 |
|---|---|---|
| 内置管理员 | 全局 | 由环境变量 `STRIDE_GPT_USERNAME/PASSWORD` 管理；不受项目成员限制 |
| admin（数据库用户） | 全局 | 所有项目 owner 权限；用户管理、系统配置、系统状态 |
| user | 按项目 | 默认可访问**未配置成员**的项目；成为成员后按角色 |

项目角色（「项目工作区 → 成员与权限」）：

- **owner**：管理成员、全部写操作；
- **editor**：生成/修改（默认角色）；
- **viewer**：只读；
- 非成员：项目配置成员后不可见；**未配置成员的项目对所有登录用户开放**（历史行为）。

> 建议：完成首个项目后立即添加成员，把项目从"开放"切换为按角色控制。

## 2. 用户管理（用户与审计页）

- **创建用户**：用户名 + 初始密码（≥8 位，含大小写/数字/符号中至少两类，不含用户名，非常见弱口令）+ 角色。
- **重置密码**：用户的密码被重置后，其所有旧会话立即失效。
- **强制下线**：递增会话纪元，该用户在所有设备上的登录立即作废。
- **删除用户**：同时吊销其会话；其历史审计记录保留。

密码策略与登录锁定（系统配置 → 安全策略）：失败 5 次锁 5 分钟，10 次锁 30 分钟，15 分钟滚动窗口。

## 3. 系统配置

**模型服务**：提供商、API Key、默认模型（LM Studio 需填端点）。Key 加密保存在服务端
（`web_config.json`，Fernet 加密，密钥文件 `web_key` 权限 600），重启仍生效。

**分析参数**：仓库分析最大 token 上限，避免超出模型上下文。

**报告模板**：Word/PDF 报告的抬头（品牌）与页脚（保密标识）。

**安全策略**：
- 企业安全基线（注入每次模型调用的额外系统指令，如"必须符合等保 2.0 三级"）；
- 对抗式复核开关（每条威胁额外一次模型调用，产出验证结论）；
- 发送前脱敏（识别 OpenAI/Anthropic/GitHub/AWS/JWT/私钥等并替换为 `[已脱敏:…]`）；
- **会话有效期**（1-30 天，持久化到数据库）。

**用量与成本**：月度预算（达到后拒绝新调用并返回 429）；按模型/用户/项目的调用与成本统计。

**API 访问**：
- 创建 Key：命名 + 作用域（read/write）+ 有效期（天）；
- 列表显示作用域、到期日、创建人、配额与最近使用；
- **轮换**：保留名称/作用域/有效期/配额，旧 Key 立即失效（新 Key 只显示一次）；
- 吊销：立即失效。
- 配额：日 token 上限、月费用上限（0 = 不限）。

**工单/通知集成**：Webhook（飞书/企业微信/钉钉/通用），可手动推送或由定时分析在
威胁变化时自动推送。

## 4. 数据备份与恢复

- 界面：系统状态 → 数据备份 → 「生成备份」→ 下载 ZIP（可选包含工作区文件）。
- 命令行：
  ```bash
  scripts/backup.sh                      # 生成备份到 ~/.stride-gpt/backups/
  scripts/backup.sh --with-workspaces    # 一并打包工作区
  PYTHONPATH=apps python -m common.backup list
  PYTHONPATH=apps python -m common.backup verify <备份.zip>
  scripts/restore.sh <备份.zip>          # 恢复（自动先备份当前状态）
  ```
- 备份包含：数据库在线快照、加密配置、密钥、会话密钥、manifest（SHA-256/行数）。
- 恢复是原子替换；恢复后必须重启 Web/API/调度器。
- 建议：升级前、批量导入前、每月定期各做一次备份，并把备份复制到其他机器。

## 5. 审计与合规

「用户与审计」页展示最近 200 条审计记录（可按用户筛选），包括：登录/登录失败/登录被拒、
退出、修改密码、创建/重置/删除用户、强制下线、保存与清除配置、创建/轮换/吊销 API Key、
创建备份、页面异常（带 `ERR-` 编号）、定时分析执行等。

结构化日志（JSON 行）位于 `<数据目录>/logs/`，可按 `trace`、`user`、`project`、
`error_id` 检索；系统状态页展示最近告警。

## 6. 常见管理操作速查

| 目标 | 操作 |
|---|---|
| 新人加入 | 用户与审计 → 创建用户 → 项目工作区 → 成员与权限 → 添加（viewer/editor/owner） |
| 离职处理 | 用户与审计 → 强制下线 → 删除用户；必要时轮换其接触过的 API Key |
| 密钥泄漏 | 系统配置 → API 访问 → 轮换；模型 Key 在模型服务中改后保存 |
| 预算超限 | 用量与成本 → 提高或清零月预算；为特定 Key 调高配额 |
| 项目隔离 | 项目工作区 → 成员与权限 → 至少加一名 owner/成员（此后非成员不可见） |
| 升级前 | `scripts/backup.sh` → `scripts/upgrade.sh` → 重启三个服务 |
